The baseline runs `/doc-detective-inline` as it stands after the rename, on 38 cases at 3 reps. It scores high, with `complete` at 0.912 across all runs. Spec-given cases reach 0.97, and cases where the session writes the tests first reach 0.83. Sessions almost never edit the doc's prose: `comment_only` failed once, on a reStructuredText step comment indented into a code block. reStructuredText is the weakest format (`complete` 0.58), then AsciiDoc (0.83). HTML and DITA scored 1.00.

The most common failure is an injected doc that holds a step Doc Detective rejects, so its dry run detects nothing. That happened in 4 of the 10 failing runs, all on generated tests (`adoc-gen-api-key` twice, `rst-gen-cli` twice). The skill validates a spec it builds, but never checks the doc after injection. Other failures are a step left out (`md-gen-open-record-new-tab`, `rst-spec-cli`), and one session that went to the wrong URLs. Three runs put an `httpRequest` step at line 3, before the text that names its URL, which lowers `placement` without failing `complete`.

The run cost $11.21, about half the estimate, at 34 seconds per session.

Round 1 had the session run `doc-detective --dry-run` on the doc after injecting into it. On a rejected step it fixes the field that stderr names, and on success it checks the plan against what it injected. It removed the failure it targeted: no run left a doc that Doc Detective rejects, and `detected` reached 1.000 on train and test. Held-out `complete` rose 0.937 to 0.952, but that gain (+0.016 +-0.071) is within noise, so the round was reverted. Train `complete` rose 0.882 to 0.902 (+0.020 +-0.104). Two train runs added more than comments: one reworded a list item in `md-spec-resource-links`, and one left a `.. step` comment as rst text in `rst-gen-sample`. `comment_only` fell to 0.961 on train.

The noise floor on test is larger than the room left to climb. Held-out `complete` was 0.937, so a perfect skill gains 0.063, against a paired CI of about +-0.07. Remaining failures are mostly systematic, the same in every run. All three `rst-spec-cli` runs leave out 2 of its 3 steps, and all three `md-gen-open-record-new-tab` runs leave out a "draft note" step. Five runs place an `httpRequest` step before the text that names its URL, because the placement rules give `httpRequest` no match value. Sessions took 35 seconds per case, with 0.7 more tool calls.

Round 1 showed the eval was saturated, so 10 harder cases were added: five new docs, each with a spec case and a no-spec case. Markdown and MDX each gained two docs, one in train and one in test, and reStructuredText gained one, in test. They target the systematic failures: `httpRequest` steps whose URLs sit in prose or only inside a code fence, a `type` and a `find` of the same text, steps inside JSX `<Steps>` components, and a reStructuredText `note` directive. Row 0b is the baseline skill on them, plus the old cases unchanged. Held-out `complete` is now 0.889, which leaves 0.111 to gain.

The new cases fail where the old ones did. All three `mdx-gen-two-tabs` runs leave out the `find` for the note the session just typed, like `md-gen-open-record-new-tab`. Two of three `rst-gen-check-api` runs wrote `runShell.output`, which Doc Detective rejects, so the dry run found nothing. One `mdx-gen-manage-orders` run also wrote a rejected step.

Writing the cases exposed two grader bugs in reStructuredText, both fixed. A step comment indented inside a `note` directive counted as prose, though Doc Detective reads it. And a `note` body counted as a code block, because the directive line ends in `::`. The 4 baseline runs those bugs affected were rerun, along with both `manage-users` cases, whose `http` fence held a blank line. That blank split the fence into two blocks for `placement`. Its doc now uses a `curl` fence. Round 1 rows are as recorded under the old grader.

Round 2 targeted the baseline's train failures. Half were docs Doc Detective rejects (`adoc-gen-api-key` twice, `mdx-gen-manage-orders` once), with fields such as `httpRequest.response.statusCode`. So round 1's dry-run check came back. One more was a typed note never checked with a `find` (`md-gen-open-record-new-tab`), so the skill now says to test every result a doc states, including text the reader just typed. At 3 reps held-out `complete` rose 0.889 to 0.938 (+0.049 +-0.109). To tighten that, both arms got 3 more reps on the test split, through a new `--split` option on the runner: 0.870 to 0.957 (+0.086 +-0.099), still inside the noise, so the round isn't kept on its own. The gains are concentrated and systematic: `mdx-gen-two-tabs` went 0 of 6 to 6 of 6, and `rst-gen-check-api` and `rst-gen-cli` 2 of 6 to 6 of 6, while `rst-spec-cli` went 2 to 1 of 6. More reps barely narrow the interval, because the spread is between cases, not between runs. `detected` reached 1.000 on both splits. Sessions took 6 seconds longer, with one more tool call.

Round 3 builds on round 2 rather than the baseline, since both of its fixes clear train failures, and is compared against the baseline. That's a second look at the same test set, so a round 3 keep needs the same margin.

Round 3 targeted round 2's one remaining train placement failure. `md-gen-api-list-users` put its `httpRequest` step after the response block, two blocks below its URL, because the skill gave `httpRequest` no match value. Now a step's `url` or `elementText` is its match value, and a step whose match sits in a code block goes after the block. `placement` reached 1.000 on both splits, from 0.926 on test (+0.074 +-0.081). Held-out `complete` was 0.944 (+0.074 +-0.101), so again it isn't kept on its own. Its failures are the ones round 2 left: `rst-spec-cli` still leaves out 2 of its 3 steps in 5 of 6 runs, and 2 `mdx-spec-glob` runs let `*/` into an MDX comment. The one train failure left is `mdx-gen-automatic-screenshots`, where 2 of 3 sessions test an illustration instead of the page's example spec.

The climb stops here at a plateau: two rounds in a row with no held-out gain beyond noise. That's a limit of the eval's resolution more than of the skill. The baseline leaves 0.130 to gain on test, the paired interval is about +-0.10, and the gains sit in a few cases, so only a near-perfect round can clear it. Rounds 2 and 3 each fixed failures that were systematic in the baseline: `detected` went to 1.000 and `placement` to 1.000 on both splits, and three test cases went from failing most runs to passing all 6. The maintainer kept rounds 2 and 3 on that per-case evidence, overriding the noise rule, so v3 is the shipped skill. More test cases, especially ones that fail like `rst-spec-cli`, would narrow the interval more than more reps.
