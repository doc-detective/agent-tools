Round 1 is the change the maintainer asked for. The hosted MCP tools aren't loaded in the eval or in many users' setups, so generate and validate now use the CLI's `validate` subcommand and `--dry-run` first. Quality didn't move beyond noise (test verified coverage +0.023, paired 95% CI +-0.082; train -0.041 +-0.066), and sessions got 27 percent faster because they no longer reach for tools that aren't there. Manni CLI docs remain the main gap (verified coverage 0.40).

Round 2 taught generate to test command-line pages in page order, scripting every file edit, commit, and shown failure. Manni coverage jumped (0.703 to 0.922) and web rose, but dd-docs fell from 0.875 to 0.625 and the held-out test score didn't move (-0.015, CI +-0.153) while train rose 0.081, the overfitting signature. It was reverted; round 3 refines it from round 2's train transcripts.

Round 3 scoped round 2's guidance to pages where the reader runs a CLI on their own files, and kept Doc Detective action pages as written. Train rose sharply (+0.180, CI +-0.107; manni 0.404 to 0.636 across all cases, with web and dd-docs up too), but with test cases rerun to 6 reps the held-out gain over round 1 was +0.013 (CI +-0.108). It was reverted. Test scores for rounds 1 and 3 use 6 reps per test case; spend includes those extra reps.

The climb stops here: three rounds in a row left the held-out score within noise, which meets the plateau rule. The noise floor on 23 test cases (about +-0.10) is larger than the gains a single skill change has produced on held-out cases, so the eval needs more test cases before another round could show a win. Round 1 is the result: the CLI-first change the maintainer asked for, neutral on quality and 27 percent faster.

Round 4 re-baselines the climb, so earlier rows aren't comparable with it. The grade now leaves `relativePathBase` at its default, so spec paths resolve against the spec file. A session's `npx @hawkeyexl/manni` runs the pinned 2.6.0, where it had fetched 4.28.0 since the isolation fix. 25 cases were added (12 web, 12 manni, 1 dd-docs), and the split is now 33 train and 40 test. The paired noise floor on test is about +-0.055 at 3 reps, down from about +-0.10, so a round can now show a win of that size.

By slice: web 0.930, dd-docs 0.574, manni 0.280. dd-docs fell because sessions write paths such as `./secrets.env` as if they resolved from the repo root. Manni fell on the shared cases. Round 1's original skills, run on those 19 cases under this harness for $7.79, scored passes 0.509 against 0.439 for the shipped skills (difference within noise), so most of that drop isn't from the skill review fixes. Manni failures are spec quality: shell quoting in `node -e` steps, scratch fixtures removed before the grade runs, and outputs copied from the page where the CLI prints something else. Spend includes the $7.79 check.

Round 5 teaches generate to make each step pass where the spec runs: field paths relative to the spec file, a command's real exit code and output, files a step needs created by the spec itself, whole command lines in `command`, and no `jq`. The changes came from round 4's failing train runs only. Test verified coverage rose 0.653 to 0.765 (paired 95% CI +0.112 +-0.103), above the noise floor, with passes up too (0.775 to 0.858). The gain is manni: test 0.301 to 0.633 (+0.332 +-0.147). Test web held (0.954 to 0.935, +-0.064). Test dd-docs fell 0.767 to 0.600 on 5 cases, with a CI of +-0.413, so it's within noise but worth watching. Sessions take about 9 seconds longer, with about one more tool call. Partway through, a stopped launch left a stale Appium lock that failed 75 web grades. Those rows are in `v5/stale-lock-rows.jsonl` and were rerun. Their $9.38 is in the spend.

Round 6 taught generate to test what the page shows. Each command the page runs is its own step, and `stdio` checks the output the page shows. The spec reproduces the problem the page shows, and runs an example spec rather than only validating it. Coverage rose on train (0.847 to 0.941, +0.094 +-0.048) and on test (0.877 to 0.923). Passes fell on train (0.838 to 0.717, -0.121 +-0.102): specs that run the page's commands as written fail more often. Test verified coverage didn't move (+0.003 +-0.079), so the round was reverted. Before the round, 7 of round 5's 16 failing train runs passed when regraded from the spec in their traces. That looked like grade-time flake, but it isn't. Each of those sessions wrote its spec with a Bash heredoc, and on Windows the Bash tool turns `\\` into `\`, even inside a quoted heredoc. The file on disk then differs from the trace. A `\n` inside a `node -e` string becomes a raw newline, and the step exits 1. Graded in workspaces rebuilt by replaying each session's commands, all 7 fail with the eval's exact step counts. Writing the spec with the Write tool avoids it. The grade now records each failing step's result description. This was the last round the stop rule allows. Round 5 is the result.

Round 7 builds on round 5 and adds one guardrail to generate: write the spec file with the file-writing tool, not through the shell. The maintainer approved it past the six-round limit, because the heredoc finding pointed at a cause rather than noise. Failing runs fell from 33 to 10, and no session wrote its spec through a heredoc. Passes rose on test (0.858 to 0.958, +0.100 +-0.075) and on train (0.838 to 0.949, +0.111 +-0.093). Test verified coverage rose 0.765 to 0.838 (+0.073 +-0.074), at the edge of noise, while coverage held. The gain is manni, where test passes went from 0.765 to 0.961. Cost and time per case held. A first launch failed all 219 sessions because the `claude` CLI login had expired. It spent nothing, and its error rows were removed before the rerun. Round 7 is the result.
